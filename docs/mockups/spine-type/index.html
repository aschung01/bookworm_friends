Read-pile spine typography

Five layouts × twelve faces × nine sizes for the title on a spine, at the geometry the pile actually draws — thickness 28–39pt and height 110–124pt from BookMetrics.from, the 5pt arch from bookSpinePath, inks from spineToneFor. Layout and face are separate controls because they are separate decisions, and because the interesting comparisons are diagonal: a serif at today’s cramped measure is not the same argument as a serif at a fixed one. The books are real titles off the shelves in the Library tab, which matters for the reason spine_tone_test.dart gives at the top of its file: a corpus of six-syllable titles makes any measure rule look fine. The defaults are the shipped drawing — layout now, face Pretendard SemiBold 13 — and should match a screenshot.

Why not the serif

            

                The obvious move — set the most bookish surface in
                    the app in the serif — is unavailable, and the code
                    already knows why.
                AppFonts.serif is cut to the 262 Hangul syllables
                that occur in app_ko.arb, and a book title is
                catalogue text. A browser cannot show you the failure
                — it always substitutes a system face for a missing glyph,
                so the line below renders complete and looks fine. That is
                exactly what makes this defect dangerous, and it is what
                fontFamilyFallback: [sans] does in the app too: not
                a box, but a silent change of family mid-title. So the
                substituted syllables are marked here from the font’s real
                cmap, read by fontTools in
                render.py rather than guessed at in the page.
                Red is a syllable Gowun Batang does not have; every red
                glyph you see is Pretendard wearing the serif’s clothes.
                Across the ten titles in this corpus, 17 fall through.
            

            


            
Notes

            

                A spine is set in a UI token.
                BookVertical uses AppTextStyles.label,
                whose own doc says “tab labels, shelf tabs, badges,
                capsules, buttons” — so in the collapsed Library tab
                the book titles are the same family and weight as the
                Library / Friends / Card labels 40pt below them.
                The design record for this feature says “the 12pt rotated
                title” twice; the code ships 13, because the token moved
                and the spine came along. label also carries
                FontFeature.tabularFigures(), right for a count and
                wrong for a title: 세계를 바꾼 테크놀로지 10 pays
                monospaced digit advances out of a measure with none to spare.
            

            

                Center hides the jitter the feature paid
                    for.
                The spec’s argument is that “a row of identical
                objects is the one thing a shelf never looks like” —
                but centring puts every title at the middle of its
                own spine, so the row has no shared datum and the ragged
                heads do not read. Head-aligning at a fixed 8pt lets them.
            

            

                Nothing scales with thickness, so thickness reads as
                    noise.
                A book’s width is its page count via
                bookThicknessPositionFromPages, which is real data
                wherever the catalogue supplied one. Sizing the title
                12.5→15pt across the 28–39pt range makes that signal
                visible, and it composes with the measure fix: thin books get
                smaller type and therefore more measure, thick books get
                larger type and a second line.
            

            

                designhouseOTFLight.otf is already in the
                    bundle, carries all 11,172 Hangul syllables, and is
                    referenced nowhere.
                The only DesignHouse call site is the auth wordmark
                at titleUser’s w600, which resolves to the
                700 file — so 376KB ships and never renders a glyph. A
                free option for a distinctive spine, with two caveats visible in
                setting 4: its Hangul is 탈네모꼴 (deconstructed), which is
                striking but wide, and Light is thin enough that
                kSpineTintMinContrast’s 4.6:1 — a floor
                tuned for normal-weight text — is no longer the right
                floor. Either adopt it deliberately or drop it from
                pubspec.yaml.
            

            

                Rejected: Hangul set upright (setting 5). The Korean
                shelf convention and the prettiest row here for short titles.
                Killed by capacity: an upright column holds about seven
                syllables against a rotated line’s eight, so the titles
                that most need help get less, punctuation sets badly upright,
                and a mixed title has to change orientation mid-string. Worth
                revisiting if titles are ever stored with a short form.
            

            

                Out of scope, found in passing: the separator hairline is 28%
                black while BookVertical._kOutline is 11%, and the
                last spine in the row is given one with nothing to its right,
                where it reads as a drawn border rather than as an edge.
            

            

                The serif faces on this page are not app assets. They are
                built by build_serifs.py into
                ./fonts/, subset to exactly the text shown here
                — about 35KB each instead of 2–13MB — so
                their size says nothing about what shipping one would cost. They exist only because the app’s own serif cannot set
                a book title, which is the finding above rather than a thing to
                work around. Gowun Batang here is that same face
                whole: it is what the pile would look like if
                AppFonts.serif were not cut to
                app_ko.arb.
            

            

                The layouts also render to PNG via
                /Library/Frameworks/Python.framework/Versions/3.10/bin/python3
                    docs/mockups/spine-type/render.py, which prints the measure arithmetic and the serif’s
                per-title coverage. See README.md beside this file.
