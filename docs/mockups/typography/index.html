Typography proposed

Which face the app should set, and what it is setting today without having chosen to. Seven options drawn on the Library screen at 1px = 1pt on a 402×874 frame — the device the reference screenshot is from, and the one ShellTabBarGeometry is measured on.

Decided — Pretendard for UI, Gowun Batang for display. Two constraints come with the pair, both recorded under the display section: Gowun Batang has no w800 and a bold lighter than most serifs' regular, so the Card figure is a real choice — see the three treatments under the display strip, where split face (serif title, Pretendard w800 figure) is the one recommended. And the serif is scoped to the fixed titles plus numeric figures, which is what keeps it at 7.2KB per weight rather than 8MB. than 8MB.

The finding underneath all of this: AppTheme._build never sets textTheme. Material seeds DefaultTextStyle from theme.textTheme.bodyMedium, so all 88 hardcoded TextStyles in the app merge onto Material 3's Roboto metrics — letterSpacing 0.25, height 1.43, color black87, and CupertinoSystemText (SF Pro Text, the optical size for ≤19pt) at every size including the Card's 46pt figure. Why Hangul is the deciding constraint

SF Pro has no Hangul, so today 소설 and 교재 are not set in the app's font — they are a fallback, Apple SD Gothic Neo on iOS and Noto Sans CJK KR on Android. Two faces in one line box means two x-heights and two weight ramps. The red rule is the baseline, the green dashed rule is the Latin x-height; where the Hangul overshoots or falls short green rule, the pair was never designed together. One row per distinct face, not per candidate: the two pairings share Pretendard for UI, so it is their serif that earns them a row of their own.

Figures: nothing in the app sets fontFeatures

SF's default figures are proportional, so a number changes width as it changes value. Every number below has four digits, so the right edge should be straight — the rule marks where it would be. It is not, and that raggedness is LibrarySheetTitle's count nudging the title, the ReadFilter capsules reflowing per year, and ReadMonthGrid's per-month counts failing to line up down the column. The last column is measured in the page rather than asserted: three of these faces ship fixed-width digits already, and for those the fix is a no-op — which couples the recommendation to the face.

Display face — the Library Card hero

A display face only earns its bundle on the largest type in the app, so this is the tile it has to justify: the Library Card hero at 1:1, plus the 22pt page title. All five are serifs with real Hangul — a Latin-only serif would reintroduce the two-face mismatch above, so it is not a candidate. Switch the frames to this face with D; it is only visible with the proposed scale on, because the current scale never sets a display face.

A display face is far cheaper than it looks, and an earlier version of this page got that wrong. It said Noto Serif KR and Gowun Batang cost 6× Hahmlet — true of the full face, and irrelevant here. A display face scoped to display, figure and title only ever renders digits and two fixed l10n strings, so subset to that it is 4–8KB per weight for every serif on this row, Hanja and all. The unscoped megabytes under each column are what you pay only if the serif is allowed to set arbitrary text. Flutter does not subset text fonts — only icon fonts, via --tree-shake-icons — so the scoping is a build step you add, not something you get for free.

Latin quality is a different question from Latin coverage. Gowun Batang has the best coverage of the five — 100% of Latin-1 and 99% of Extended-A, against Nanum Myeongjo's 41%/12% and Song Myung's 5%/0% — and its Latin is genuinely drawn rather than borrowed. But it is also the lightest: its w700 stem measures 250, thinner than Hahmlet's and Noto Serif KR's w400 (261 and 266). With no w800 either, a 46pt figure in it reads refined rather than dominant — worth deciding deliberately, since stat_tile.dart says the figure should be "the thing you see first".

Which makes one rule load-bearing. StatTile has a figureIsText mode that renders an author's name at figure size. A name is arbitrary text, so it has to stay in the UI face: if the serif covers that tile, a scoped subset shows tofu on the first author it has no glyphs for. The serif covers numeric figures and the fixed titles; figureIsText does not.

The Card figure — serif or Pretendard?

The figure is the one place Gowun Batang's lightness fights the design: its w700 is its heaviest, and stat_tile.dart wants this number to be "the thing you see first". Three ways out, at 1:1. The title is serif in all three — only the figure changes. Weights are capped at what each face actually has, so nothing here is faux-bolded.

Thirteen sizes today — 10.5, 11, 11.5, 12, 12.5, 13, 14, 15, 16, 17, 18, 20, 24, plus 26/30/46 in StatTile — and six weight spellings, of which bold and w700 are the same weight written two ways. Seven tokens and three weights below. Pick a face to set it in.

What this page does not settle

Bundle cost. Pretendard is not on Google Fonts and ships as a ~1.5 MB static per weight or a 6.7 MB variable; the Pretendard-Std subset (2,780 common syllables) is the version worth measuring, at three weights. Noto Sans KR, IBM Plex Sans KR, Gothic A1, Hahmlet and Gowun Batang are all Google Fonts and all OFL, and the two serifs are only proposed as display faces — for the page title and the Library Card figure, which is the shareable artifact and the app's one keepsake screen. Keeping the system face for UI and adding an explicit fontFamilyFallback is the zero-bundle option and is the second frame.

The faces here are subset to this page's glyphs and inlined by build-fonts.py, so this page renders the same offline as on. It is not a licence audit and it is not a performance measurement.
