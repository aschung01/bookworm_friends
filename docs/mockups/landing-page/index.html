libstack.app — the host the card points at

Nothing built; the host is bought and empty. libstack.app was registered 2026-08-20 and resolves to Vercel nameservers with nothing served. This page draws what has to answer there — and it is not one thing. Task 10 of docs/superpowers/plans/2026-08-19-phase-5-card-sharing-plan.md calls it “the landing page”, but the host has four jobs and only the first is a landing page: /, then /@handle, then a per-handle Open Graph head, then two .well-known files at the domain root. Read hold-kk first — it is the only one 5a cannot ship without.

Settled by Task 10, and drawn here as given: the host is Vercel, not a Supabase edge function, because the deep-link files want exact content types at the root; the web host never holds the service-role key and reads through one SECURITY DEFINER RPC, public_card(handle), so a leaked env var exposes public cards and nothing else; a private profile 404s. Three things the drawing added. /@handle 404s for the whole of 5a even though Task 2 prints that exact URL into the artifact as pixels (hold-at). The private 404 and the unknown 404 have to be byte-identical or the route becomes a way to enumerate handles and detect who has gone private (card-404). And /privacy and /support are absent from the plan while the store listing in this same phase cannot be submitted without them (page-privacy). Five red callouts; nothing here is finished.

Sourced from the real code. Tokens are app_theme.dart’s: pageBackground #F8F9FA, primaryText #212529, and brandText #067657 on the single call to action. The card is not redrawn. Every artifact here is the app’s own artifact(), shared with docs/mockups/library-card-share/index.html and called at --u 0.7–0.85 instead of 2, so the web page cannot disagree with what the phone exported — production uses the hosted PNG instead, and el-embed is why that trade goes the way it does. The card stock (--stock #F2EDE0) is a proposal, not a token, and only the card-stock version depends on it. The phone is the same 170×340 frame the app screens use, with a messenger’s webview bar where the app’s would be — deliberate, because every visitor arrives by tapping a link inside a chat thread, so that is the real viewport and the 206px desktop browser is the footnote. Fixtures are the two readers the card was reviewed against: 12 books, and the median reader’s 2. Filter with /.
