Library shell — design mockups

Static mockups from the brainstorming session that reshaped the app around a Flighty-style bottom tab bar, a persistent library background, and a per-tab bottom sheet — plus the Library Card, our answer to Flighty's Passport.

Screens are in chronological order, so later ones supersede earlier ones. Colours and metrics come from the real tokens in app_theme.dart: pageBackground #F8F9FA, surface #FFFFFF, brand #09BC8A, brandText #067657. Book covers are face-out with per-ISBN size jitter (BookWidget); the read pile is brand-green spines at 0.4 / 0.7 / 1.0 opacity (BookVertical).

Generated pages. Fragments live in _src/; rebuild with sh docs/mockups/library-shell/_src/build.sh after editing one. Open this file in a browser — no server needed. The numbered screens below are the session history; for the settled design only, use Decided design, where the two decisions still open are branched as versions you can switch between or diff side by side.

decided.html is not part of the _src/ build — it is built on the design-mockups skill shell, which supplies the filtering, flows and version machinery. Edit its data sections in place.

Settled decisions

The axiom, corrected
We borrowed Flighty's persistent background, but the globe is one shared space — your flights and a friend's are drawn on the same Earth, so panning between them really is one world. A bookshelf is personal property. Yours and jisoo's are two different objects, so swapping the background was substituting one for the other, which is why “where did Friends go?” and “how do I get back?” kept biting for four rounds and nine versions. Corrected: your library is home and is always the background; a friend's is somewhere you visit. Naming it a visit gives departure and return for free. Drawn as visit-model.
Praise is one emoji, not text
“Praise” (칭찬하기) writes book_compliments from the fixed 16-emoji palette in praise_palette.dart; varchar(6) is sized for one emoji, since ❤️ alone is two code points. It is the only persisted social object in the app — poke_user() fires a push and writes no row — so praise is what Activity can be built from today, and it is the payoff of a visit. It is gated to finished books: _ComplimentButton returns SizedBox.shrink() unless status == 2, so praise is for accomplishment, never for what someone is currently reading.
Book details, redrawn from the widget
The mockup's details page was wrong and has been rebuilt against book_details_tab_view.dart: circular back button; delete and edit only on your own book; a 180px cover standing on a shelf with its label; the status badge in the top-right corner — the corner the Praise button takes over on a friend's book, which is why a friend's badge moves down above the shelf label. Then title, authors (from the search API, since books has no author column) and the reading-period card, shown only when status >= 1 and a start date exists. Finally the pinned Book info / Notes tabs. There is no Status/Shelf/Rating list and no inline memo — both were invented.
Name
Library Card (도서관 카드) — our Passport equivalent.
Architecture
A library is always the background; each tab's content lives in one bottom sheet. Any sheet drags down to its title, revealing the library beneath. The library is never drawn twice.
Tab bar
Floating pill — Library, Friends, Card — plus a detached circular search button that opens Add Book as a modal at 95% height. Real Liquid Glass on iOS 26 via cupertino_native_better, blur fallback elsewhere.
Encasing
Preserved: white surface bar with elevation 4 above, #F8F9FA well between, white sheet with an upward shadow below.
Bar
“My Library” (new l10n key) with share and profile; a friend's view shows “jisoo's Library” with Poke instead. Edit and + are gone — long-press a book to edit, search button to add. Edit mode swaps in manage-shelves and Done.
Read books
One sheet, two snap positions: collapsed is today's spine pile with the count; expanded is covers grouped by month. Sheet position replaces any Shelves/Read toggle.
Filters
iOS 26 capsules when expanded, glass popover select when collapsed. Month-level filtering dropped — the grid is already grouped by month.
Library Card
Stats and shareable artifacts only — the Card carries no read-books list. Read books belong entirely to the Library tab, which already groups them by month, so a sortable Date / Title / Author / Rating list here would be a second home for the same data.
Friends
Sheet titled “Friends” with Everyone / Activity capsules and an icon-only Add Friend (home for search_user_page). Everyone lists friends with what they're reading and their read count; it works on existing data, so Activity can ship later. The avatar rail appears only once a friend is selected, and holds friends only — not you.
Friend paging
Horizontal swipe pages between friends, as PageView does today — scoped to inside a visit under visit-model, with the rail as the map showing how many are left in each direction.

Where it landed

★ visit-model answers 1 and 2
Friends stays a real destination — a hub of people and what each is reading, not a picker you summon. Tapping someone enters a focused visit: the tab bar steps aside because it cannot honestly report a position there, the rail becomes the visit's own chrome, and the glass × at its head ends the visit. Decision 2 is answered rather than dodged, because a visit is a thing that has an end. Decision 1 is reframed: mechanically close to pushed-page, but for the opposite reason — not a page that unfortunately covers the tab bar, a focused context that should. Your own library keeps the persistent background, which is the part of the world rule that was always true.
✓ Received praise is visible again
_ComplimentButton and the received-emoji block both sat inside if (!isSelf), so the person praised never saw it anywhere in the app — the push notification was the only trace. Hiding the button is right, since you should not praise yourself; hiding the praise defeated the point of storing it, and book_compliments is the only social action that is stored at all. Fixed in e67ca75, which also retired ComplimentBlock from being dead code — it was never referenced, and its List<dynamic> fallback would have rendered Instance of 'BookCompliment' if it had been. Pinned by book_details_compliments_test.dart, which fails without the fix.
Praise is the peak, but it is buried
The real path is four taps and runs through book details, where _ComplimentButton actually lives: cover → details → Praise → emoji. The emoji then sit under the title on that detail page — rendered by ComplimentBlock, which e67ca75 put to work. So nothing on any shelf hints that praise exists, in either direction: you cannot see that a friend's book can be praised, and you cannot see that yours has been. Drawn as a labelled proposal (“Proposed — not built”) rather than folded in as fact.
✓ One praise per person per book, live
Settled, enforced, and applied to the hosted project on 2026-08-15: the compliment_uniqueness migration adds UNIQUE (book_id, from_user_id). Praise was already scoped to one person's copy of a title — book_compliments.book_id points at books, which is per-user, so jisoo's Pachinko and minho's are different rows and never share praise. What was missing was uniqueness, and reads were too narrow: the old policy showed a third visitor nothing but their own praise, which would have made a count mean something different to every viewer. Reads now follow the book's own visibility. A tap is a toggle: the same emoji withdraws, a different one replaces, and the Praise pill wears your own emoji so you can tell which is yours among chips that do not name their senders. Pinned by praise_toggle_test.dart, and verified against the real database: all 39 rows were already unique so nothing was deleted, a third party went from seeing 0 of a book's praises to 2, the old bare insert now fails with a duplicate-key error, and the upsert swaps the emoji in place without adding a row.
tab-only, rejected
Judged worst on UX, and rightly: the rail and the swipe are a matched pair — the rail is the map, the swipe is the movement. Deleting the map to fix a 33px layout collision was optimising pixel cost over comprehension. The collision is a geometry bug, not an argument against the affordance. rail-me and tab-follows-world are superseded with it, along with the four standalone way-back controls, whose job the visit's × now does.
Still open
The palette does not match the data. 28 of the 39 live praises are emoji outside the fixed 16 — 🦄 🐲 🧸 🛸 ☘️ ☃️ — left by an older version with a free emoji keyboard (the rows date from 2022–2024, carried over from the archived project). They render fine, and the pill still shows yours, but they highlight nothing when you re-open the palette, and a CHECK pinning the column to the 16 would reject them. Migrate them onto the palette, widen the palette, or leave it unconstrained — not yet decided. Praise is also still discoverable only from a detail page: the shelf hint that would advertise it costs a new shelf-level count query, so it stays a proposal. And the bar-to-sheet clearance on friend screens measures 5.8px in every version, main included — a pre-existing tightness worth fixing globally, and not caused or cured by any version here.

Superseded explorations

1 — Friend transition
Screen 11. “Sheet grows” is ruled out: it recreates the duplication and nests paging inside a draggable sheet. What survives is a background swap with the rail dropping in, drawn as main, versus a pushed page, drawn as pushed-page. Statically they differ only by the tab bar; the decision is what happens to the persistent world. Note that home_page.dart already nests horizontal drag-reorder inside the friend PageView, and already gates paging physics by mode — so the swap's cost is choreography, not gesture arbitration.
2 — Returning to the Friends list
With your own avatar out of the rail, tapping the already-active Friends tab is the only free affordance left, which makes it load-bearing rather than a nicety. main draws that; four explicit alternatives branch off it — back-chevron in the bar, rail-close as a glass × pinned at the head of the rail, rail-me as your avatar there instead, and sheet-back as a named ‘‹ Everyone’ in the sheet header. The new Returning to the Friends list flow exists to make the comparison concrete — and it shows the problem, since the settled version's middle step has nothing to draw. Moot under pushed-page, where swipe-to-dismiss is the way back; that version drops the callout entirely.
What drawing the options found
rail-close is the cheapest — zero pixels until a friend is picked — and the only control whose semantics match mechanic C, since the rail is the selection and a × clears it rather than implying you navigated somewhere. Its open question is material: it would be the third glass surface on one screen. sheet-back breaks its own layout: collapsed, back label + title + count + filter do not fit 170px, the title wraps and the spine pile is pushed under the tab bar — so the name it exists to show is exactly what does not fit.
The permanent rail is self-undermining
rail-me reads best of the controls, and drawing it on every state it would have to appear on — nine screens, the Card included — showed why it cannot stand. The sheet is a share of the frame measured from the bottom, so a rail above it does not push it down: the clearance under the bar falls from 38.8px to 5.8px, and tips into outright overlap at the smaller size the flow steps are drawn at. The fix is a shorter expanded sheet, or hiding the rail when the sheet is up — and hiding it makes the rail conditional again, which is the premise collapsing. How much margin survives at real device metrics needs checking in Flutter rather than settling from a mockup.
3 — Is the tab bar a control or a readout?
Raised by tab-follows-world and its rail-less sibling tab-only: swiping moves the background and the tab highlight together, so your own library is the leftmost page rather than a different mode. Decision 2 dissolves — the way home is the Library tab, already on screen and already named — and the friends list becomes a modal picker you summon, which is what stops the Friends tab meaning two things at once. Both also settle decision 1 by side effect: a tab bar can only report position if it is on screen, so pushed-page is off the table. The shared costs are a tab bar that changes selection without being tapped, and one of three tabs behaving as a picker rather than a destination.
Rail or no rail
tab-follows-world keeps the permanent rail and inherits its clearance problem; tab-only drops it and is identical to main on all five of your own screens, the Card included — it charges nothing for the states where you are not looking at a friend. It is also the only version that deletes a component: the rail leaves the UI-elements gallery entirely. What it gives up is the map — nothing says how many friends there are or where among them you are, and no affordance says the background can be swiped at all. Page dots would be the small answer if that turns out to matter.

Phasing

1 — Shell
Tab bar, one-world/one-sheet architecture, chrome removal, per-tab sheets, drag-down gesture, friend selection swapping both layers. No new data. Includes splitting home_page.dart, already 1,271 lines.
2 — Read view
Month grouping, cover grid as the expanded state, capsule date filter. No new data.
3 — Library Card
Stat providers, card UI, share. Needs books.page_count and books.authors plus a backfill; both are already returned by every search provider and currently discarded.
4 — Friends activity
Feed query for the Activity tab. Optional poke_events table if pokes should appear in it.
