Libstack — friends & invites

Screens

Moving from a one-directional follows row to mutual friendship, with invite links as the only path in — no handle search, so no request queue and no badge. Modelled on Flighty and checked against its real flows.

Drawn in the app's own materials: colours from lib/constants/app_theme.dart (brandFill #067657, surfaceVariant #E9ECEF, secondaryText #626A72, softRedColor #D9433A), and the real typefaces loaded off disk from assets/fonts/ — Pretendard throughout, GowunBatang on the single serif token. Every size is a real token from app_text_styles.dart scaled by 0.615, so these frames are metrically faithful rather than merely tidy. The books are too: a shelf book is screenHeight * 0.15 tall and height / 1.6 wide (shelf_row.dart:208), the cover is a colour block over a title from kGeneratedCoverPalette (generated_cover.dart:12), and the binding band is 8.2% of the width (book_geometry.dart:340). Drawn at 40% of that, as the first pass did, a library reads as a row of loading skeletons.

Chrome is post-redesign: the Friends sheet is the switcher, and a visit is ✕ / the friend's library / Poke, with no tab bar at all. Full-screen sheets are laid out the way the reference lays them out — illustration at the top, copy in the middle, fine print then the action on the floor. But only where there is an illustration to carry the middle. A screen pinned at the top and the floor with nothing between frames the emptiness instead of using it, which is what three of these screens did; they now flow from the top, and a destructive confirm is the app's own AlertDialog.adaptive rather than a page. That rule is asserted, not trusted — see verify.py. Two versions — switch with v, filter with /, change view with 1 2 3.
